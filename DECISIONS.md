# Decisions

Every decision about this compiler, in the order it was made. A decision lives twice: in the document that
teaches that part of the compiler, which is where the rule is, and as a row here, which says when it was made,
by whom and why. A decision that exists only in a conversation will be re-litigated.

**The log is append-only.** A row is never edited, renumbered, reordered or removed. A decision that changes an
earlier one is a new row that names the one it supersedes ("superseding D1"), and the document that teaches
the rule is changed to match.

**How to add a row:** append one line at the end of the table: `| date | **Dnnn** (decided by Mortaro): what was
decided, in a sentence or two, and why |`, with the next free number. A proposal an agent makes is written
"(proposed by Claude, unconfirmed)" and never recorded as decided; a row that only builds a decision says so,
"(implements D157; ...)". Then put the rule itself into the document that teaches it, in the same commit. With
more than one agent running, edit this file only by appending, match on the surrounding text rather than on line
numbers, and re-read it immediately before writing it (`AGENTS.md`).

## Decision log

| Date | Decision |
|---|---|
| 2026-10-19 | **D1** (decided by Mortaro: "the first line of the program should be a load to the standard library instead of the auto search, very explicit"): **a program names the standard library in its first line, and the compiler follows the load lines.** The compiler does not go looking for a library, and there is no environment variable that names one: a program says which folders it loads, the compiler reads them, and a name that resolves to nothing is a crash. The library is a folder like any other, so anyone can bring their own, and the compiler is the same for all of them. |
| 2026-10-19 | **D2** (decided by Mortaro: "the idea of a Launcher goes away, the user program is the entrypoint and it loads the standard library + its os environment"): **there is no launcher.** The user's program is the entrypoint, and it loads the standard library and the folder of its operating system itself. The compiler does not read a `launcher/launcher.spite` and does not load anything the program did not ask for. |
| 2026-10-19 | **D3** (decided by Mortaro: "our compiler will NOT deal with any C code"): **the compiler writes machine code.** A 32-bit PE for Windows, written by the emitter, with no C in between: no C is written, no C is read, and no C compiler is needed to build a program. The standard library is imported from another repository and is not part of this one. |
| 2026-10-19 | **D4** (decided by Mortaro: "for now its okay that the user cannot reopen methods from standard library he mostly only needs to add methods to the standard library anyway"): **a class may be reopened, and the standard library's own methods keep the priority.** A later declaration replaces an earlier one of the same name, and the names the later one does not have are kept, so a program may add to a class of the standard library. For now it may not replace the methods the standard library declares: the standard library's declaration of a name is the one that runs, and a program that declares the same name is refused rather than silently losing. |
| 2026-10-19 | **D5** (decided by Mortaro: "a class that 'lost load priority' should not replace the current in memory code"): **the declaration that wins the load order is the one the program runs, and a change to a file that lost is not a change to the class that runs.** The load order decides which declaration of a name is the class's, and that fact is written down when the class is compiled, because the hot reload compares a save against it: a save in a file that only loses leaves the code in memory alone. |
| 2026-10-19 | **D6** (decided by Mortaro): **the program's exit code is the value its entry constructor answers.** A constructor that answers nothing leaves the exit code at 0. The original sets the exit code by calling `Program().exit(code)`, and that is not lowered yet. |
| 2026-10-19 | **D7** (decided by Mortaro: "create a new folder under D:/Projects called SpiteSpec and inside it a tests subfolder, for each thing we test we move a program there update it to the new format and run those examples from there, so later it gets shiped as its own repo with up to date tests instead of mixed things"): **the tests live in their own repository, `D:/Projects/SpiteSpec`, and not in the compiler's.** This repository is the compiler and nothing else. One folder per program under `tests`, named after what the program is, each standing on its own, and each ported to the new format when the part of the language it needs works. |
| 2026-10-19 | **D8** (proposed by MiniMax M3.1 Flash, unconfirmed): **a function is named by the class that owns it and its own name, and a call names the class that owns the function it reaches.** `Counter.reset` and `Timer.reset` are two functions, so a call that says only "reset" says neither, and the reachability pass cannot tell the two apart. A call whose owner the compiler cannot tell yet names no owner at all, and the passes that need one fall back to the name alone, which keeps every function of that name. |
| 2026-10-19 | **D9** (proposed by MiniMax M3.1 Flash, unconfirmed): **the class of a receiver is the class of the value the receiver holds, and the builder answers it.** The builder knows the class of a name from the type the name is declared with, from the class a constructor call makes, and from the name a value was copied from. The name resolution is the step that resolves types, but it answers the types of declarations, not the class of a receiver in the middle of a body, and the builder is the step that reads the body. |
| 2026-10-19 | **D10** (proposed by MiniMax M3.1 Flash, unconfirmed): **a member read on a type parameter is a codegen value, and the name resolution notes it instead of refusing it.** The original compiles a generic class once and hands it the type argument at run time, so `$value_type.key_type` is the key type of whatever the argument is, and the compiler cannot know it while it reads the class. The standard library writes exactly that, so refusing it would stop the library from being read. The member is a note, and the answer comes when the class is compiled. |
| 2026-10-19 | **D11** (proposed by MiniMax M3.1 Flash, unconfirmed): **the name resolution answers the class every function of every class answers, and the builder asks it.** The class a call answers is the result type of the function it reaches, and a result type is a type, so the step that answers types answers it. The builder holds one file at a time, so it cannot read another class's file to find that result type, and reaching back into the symbols would break the shape of the pipeline. |
| 2026-10-19 | **D12** (decided by Mortaro: "the original rules, but made as standalone optimization passes for each possible proof so its easy to maintain instead of one bigass file"): **where an object's block lives is a decision the compiler makes, one proof at a time, and each proof is a pass of its own.** The original puts an object that never leaves its function in that function's frame and the rest on the heap, so the frame is the first proof and the heap comes with the runtime. The passes live beside the other passes, one proof each, so that the placement is easy to maintain and each proof can be checked on its own. |
| 2026-10-19 | **D13** (decided by Mortaro: "lets start using that one as source of truth for standard library, we move the files there but we dont make anything implicit" and "do not move the entire standard library to a new folder at once, move them as the symbols are needed, and update them to the new explicit version as you move"): **the standard library lives in `D:/Projects/SpiteStandardLibrary`, and it is written again with nothing implicit.** The classes move there one at a time, as the compiler needs them, and each one is rewritten as it moves: a class that needs memory holds a `Buffer` and says how much room it needs, and the methods the compiler used to supply are written in the library. The old compiler keeps the library it has until it is retired, because its rules are written against the paths there. |
| 2026-10-19 | **D14** (decided by Mortaro: "for now we use the c library but isolated as a spite file using DynamicLibrary for it. classes in Spite only use Buffer to refer to the memory they need and the compiler optimizes it based on the proofs we have"): **the memory of an object comes from the C library, and the library reaches it in one file.** The heap is Spite in one file, and it reaches the C library through `DynamicLibrary`, so the compiler needs to call a function in a DLL by name and nothing else. A class names the memory it needs with a `Buffer`, and the compiler places it and optimizes it from the proofs it has, so a program never thinks about memory. |
| 2026-10-19 | **D15** (decided by Mortaro: "we should go with fastest option that also becomes the most flexible for different cases... we need a way that keeps standard library as high level as possible and hides those specifics in the compiler itself"): **the compiler owns the memory, and the library only names things.** There is no one way to deal with memory: the compiler changes where a block lives, and how it is aligned, from what it proves, one proof to a pass. The library says what it needs in high level words and the compiler answers it: a class that needs room holds a `Buffer` and the compiler lays it out, a foreign call names the C function and the C library and the compiler writes the bytes, resolves the address once, and calls through it. The library never names an address, a byte count of memory it borrowed, or an allocator. |
| 2026-10-19 | **D16** (decided by Mortaro: "all the methods that were previously implicit to be explicit, and instead of using 'this' we refer to the read of the buffer"): **a value is read from its room, and `this` is the place the room is kept and never the value.** A class that needs memory holds a `Buffer` and says how many bytes it needs, the compiler lays that room out at the front of the class's block, and the class reads its value with the buffer: `_buffer.read_byte_at(0)`. A method of such a class is therefore made on the address of the value, and the receiver of a call on a value class is that address. The library names the methods that read and write a byte, and the compiler writes their bodies, because reading a byte of memory is not something Spite can say. |
| 2026-10-20 | **D17** (proposed by MiniMax M3.1 Flash, unconfirmed; supersedes D16's spelling): **the library names the two methods that read and write a byte of a room, and the compiler writes their bodies: `_read_byte_at` and `_write_byte_at`.** They are private, so a program reads the bytes of a buffer through the buffer's own methods and never through these two. D16 named them `read_byte_at` and `write_byte_at`, but the library's own `Buffer` has methods of those names, and one name cannot mean two things. |
| 2026-10-20 | **D18** (proposed by MiniMax M3.1 Flash, unconfirmed): **a crash and an assertion stop the program, and the program says where it stopped.** A `crash` stops the program when its condition holds, an `assert` when it does not. The compiler builds the text while it compiles the program, the text names the file and the line, and the program writes it to the standard error and leaves with a code of 1. The original's crash reports are richer, and the crash report map is still to come. |
| 2026-10-20 | **D19** (proposed by MiniMax M3.1 Flash, unconfirmed): **the sections of the executable grow with what they hold, and the code comes last.** The imports, then the data, then the code, each where the one before it ends, and the image is as big as the last section needs. The code comes last because its size is only known once every instruction is written, and the imports and the data come first because the code needs their addresses while it is written. Before this the sections sat at fixed addresses, and a program whose code was bigger than a section had its sections laid over each other, and the file would not load. |
| 2026-10-20 | **D20** (proposed by MiniMax M3.1 Flash, unconfirmed; supersedes D18): **a `crash` stops the program when its condition does not hold, exactly like an `assert` does.** The language's rule is that a `crash` mirrors an `assert` with the other severity, so `crash index >= 0 and index < count` stops the program when the index is outside the count, and not when it is inside. D18 had it the other way round, and the library's own conditions are written the language's way, so a `crash` that was meant to catch a mistake caught the good case instead. |
| 2026-10-20 | **D21** (proposed by MiniMax M3.1 Flash, unconfirmed): **an index is a call to `get_at`, and the high representation is where that is written.** `a[b]` is only a shortcut for `a.get_at(b)`, so the builder lowers it to a call: the receiver is the value that is indexed, and the index is the argument. The compiler's own `[]` is not a machine operation, and the language's rule is that every `[]` of a class of your own is a `get_at` the class declares. |
| 2026-10-20 | **D22** (proposed by MiniMax M3.1 Flash, unconfirmed): **the receiver of a call on a value class is the address of the value.** A value class keeps its value in its room, and the room is the place the value is kept, so a method of such a class is made on the address of the value and not on the value itself. When the value is an attribute of the class, that address is the address of the attribute; when it is a place of the frame, it is the value the place holds. Reading the value instead of its address gave a method of a value class the byte where the room was, and it read past the room. |
| 2026-10-20 | **D23** (proposed by MiniMax M3.1 Flash, unconfirmed): **writing an index is a call to `set_at`, and the high representation is where that is written.** `a[b] = v` is a shortcut for `a.set_at(b, v)`, the same rule a read follows, and the builder lowers it to that call. The compiler has no machine operation for an index: the index is a call the class declares, so the class that owns the memory says what an index means. |
| 2026-10-20 | **D24** (proposed by MiniMax M3.1 Flash, unconfirmed): **a minus in front of a value is a subtraction from zero, and the builder writes it.** The parser reads `-1` as a unary expression over the number `1`, and the builder lowers it to the subtraction of zero and the value, so the emitter writes one subtraction and the number it holds is the number that is written. Before this a negative number was read and then dropped, and a function that returned `-1` returned whatever was in the register. |
| 2026-10-20 | **D25** (proposed by MiniMax M3.1 Flash, unconfirmed): **an argument of a value class is the address of the value when the value is an attribute of another object, and the value itself when it is a name of the class the code is in.** The room of a value class is kept inside the object that holds it, so an attribute of another object is reached through its address, and the callee reads the room there. A name of the class the code is in is a plain number of that class, and the callee wants the number, not the place the room is kept. Before this every argument of a value class was passed by address, and a plain count was passed as the place its room is kept, which wrote the count over the room. |
| 2026-10-20 | **D26** (proposed by MiniMax M3.1 Flash, unconfirmed): **an object that is returned is copied into the frame of the caller.** The block of a returned object belongs to the frame of the function that made it, and that frame is gone when the call returns, so the caller copies the block into its own frame and holds the copy. The copy is of the whole block, the room and the attributes of the class with it. |
| 2026-10-21 | **D27** (proposed by MiniMax M3.1 Flash, unconfirmed): **a generic class written in a call is monomorphised the same way as a generic class written as a type, and the name resolution publishes the name of the instance.** `List<String>()` names the instance `List_of_String`, and the builder lowers the call to that instance, for the owner of the call and for the class the call answers, so the methods the call reaches are the ones of the instance. The name resolution is the step that mints the instance, so it is the step that says which instance a call names, and it says it per class: a template body writes `List<$element_type>()` once and means a different instance in every instance of the template. |
| 2026-10-21 | **D28** (decided by Mortaro: "i also want to separate error validation layer into its own folder so we have something like a Validator that each validator can take whatever step it validates from but it makes clear whats an error"): **every error is decided by a validator, and validators have a folder of their own.** `validators/<level>/<rule>/` holds one rule: a class `Validator(input)` that takes the one representation the rule reads and answers the problems it finds, and a `contract.md` with the rule, its exact texts, the heading of the specification and the program that proves it. A validator never changes its input, and a step never writes a problem. A rule lives at the earliest level that holds the facts it needs. The rule is in [ARCHITECTURE.md](ARCHITECTURE.md#validators). |
| 2026-10-21 | **D29** (decided by Mortaro: "i want to completely separate any 'printers' from the internal representations. the formater should be a printer that takes an AST and prints spite code with its own folder for example, final classes uses it. writing any level of IR to a file for humans to read also have their own separated printers"): **nothing turns a representation into text but a printer, and printers have a folder of their own.** `printers/<what>/` holds a class `Printer(input)` answering `text()`. The formatter is `printers/spite`, a tree printed as Spite, and `--final-classes` is the same printer given the merged class; the reports, `--high-ir`, `--low-ir` and `--optimization-report` are printers too. A representation holds no function that writes it as text. The rule is in [ARCHITECTURE.md](ARCHITECTURE.md#printers). |
| 2026-10-21 | **D30** (proposed by Claude Opus 5.5, unconfirmed; follows from D28): **a step never fails: what it cannot build it marks, and the validator of that level turns the mark into the error.** The lexer, the parser, the mapping, the name resolution, the builder and the lowering each put a marker where they could not build, and go on. So every error text is in a validator, nothing a step could not build is dropped (the builder's `skipped` count let an executable be written without the statements it skipped), and one file answers all its syntax errors at once. A generator given a marker crashes naming the fault of the compiler. The rule is in [ARCHITECTURE.md](ARCHITECTURE.md#steps-never-fail). |
| 2026-10-21 | **D31** (decided by Mortaro: "the messages do not need to be exact same, as long as they convey the same information and are both validating the same problem. we dont want to polute the steps with error messages and strings instead we pass them to validators that can run imediately, as soon as we find an error we report instead of continueing uselessly"; supersedes D30): **a step hands what it found to a validator at once, the validator owns the words, and the first error stops the run.** A step holds no error text: it calls the validator of the rule with the data (a token, a node, a folder), and the validator either lets it pass or reports the problem and ends the compile. An error message says what the old compiler's says, in the words this compiler chooses. |
| 2026-10-21 | **D32** (decided by Mortaro): **objects are freed by reference counting**, as in the old compiler: the compiler writes every count change and frees an object when its count reaches zero, so `--debug-memory` balances. Placing an object in a frame instead of the heap is a proof and a pass of its own, later. |
| 2026-10-21 | **D33** (decided by Mortaro: "we might need to already optimize how buffers work now, so things dont waste space if we can proove they will never need extra space since buffer will decide everything else in the language and might be to intertwined to change later"): **a Buffer's room is sized by the compiler.** `Buffer(size)` names how many bytes a value starts with. When the compiler proves a buffer never grows (only read and written inside its size, as the room of a number is), its bytes sit inside the value that holds it, exactly that many. Every other buffer keeps its bytes in a block on the heap that grows. The library writes the same Spite for both; the compiler decides which one each buffer is. |
| 2026-10-21 | **D34** (decided by Mortaro; supersedes the 32 bits of D3): **the generator writes 64-bit code for Windows**, with the Windows x64 calling convention. |
| 2026-10-21 | **D35** (decided by Mortaro: "we shouldnt even have those internal classes anymore, the compiler simply does the work, everything in standard library should be things a user can actually use"): **the standard library holds only classes a program uses; the machinery is the compiler's.** There is no `Memory.Heap`, `Memory.Arena`, `Memory.Inspector`, `Anything`, `Nothing`, `Symbol` or `Build` class and no `Spite.*` reflection class in the library: memory, symbols, build settings and reflection are compiled in where a program reads them. User-facing classes (`File`, `Parallel`, `Vector`, sockets, JSON and the rest) move into the library, rewritten explicitly, when a program needs them. The tests that measured the old allocator through `Memory.Heap` are removed; allocation counts return as `--debug-memory` expectations with the passes that place memory. |
| 2026-10-21 | **D36** (decided by Mortaro: "user shouldnt even be able to inspect for those things, we write in spite and things simply work, so we are never locked on limitations for optimizations" and "those classes are not \"emulated\" they do not exist, memory and concurrency are language internal constructs for each emitter"; refines D35): **memory and concurrency are constructs of the language that each generator implements, and a program cannot observe them.** No class stands for them, not even one the compiler fills in: there is no memory address, allocator, allocation count, object placement or list of live instances a program can read (`Memory.*`, `x.memory`, `Monster.instances` are gone). `Parallel`, `Concurrent` and the rest of concurrency are words of the language that each generator compiles its own way. So no optimisation is ever blocked by something a program might be watching; only `--debug-memory` reports leaks, outside the program. Reading the declared shape of a class (its attributes and functions) stays, since it is fixed while compiling. The tests that observed memory or live instances are removed. |
| 2026-10-22 | **D37** (decided by Mortaro: "library classes for reflection actually exist and are reopenable, just hardware management gets hidden like memory and concurrency/parallel"; corrects D35): **reflection is library classes; only the management of the hardware is hidden.** `Spite.Class`, `Spite.Namespace`, `Spite.Function`, `Spite.Attribute`, `Spite.Argument` and the rest are ordinary classes of the standard library that a program may reopen, and the compiler fills them in and folds every read it can while compiling. What has no class is the hardware: memory (heap, arena, addresses) and concurrency and parallelism, which each generator implements (D36). |
| 2026-10-22 | **D38** (decided by Claude under D509; follows from there being no launcher): **the compiler takes only its own flags, and a program checks its settings when it reads them.** `--name=value` sets a field of `Build`, and anything else is refused as no compiler option; an `Environment` setting is given to the program when it is run, and the program's `Environment` reads and checks it. So the old checks the compiler made on program settings it passed on (a `--` separator, a setting's value or spelling) and the messages for the old compiler's removed flags (`--run`, `--executable`, `--translation-units`, `--tune-for-this-machine`) are retired. |
| 2026-10-22 | **D39** (decided by Claude under D509; follows from D36): **the spec programs that name a hidden class are rewritten or retired.** A test that uses `Memory.*`, an allocator, `Lock`, `Atomic`, `Scheduler`, `ThreadPool`, `ThreadLocal` or `ThreadSlot` only on the way to something else is rewritten without it; one whose point is that class moves to `SpiteSpec/retired/`, with a line saying what it checked, so the behaviour can be rebuilt as a language construct. To confirm. |
| 2026-10-22 | **D40** (decided by Claude under D509): **a crash flushes the console first, so a program's output reads in the order things happened.** The old compiler wrote the crash report before the output it still held; spec programs whose only difference was that order take the new order. To confirm. |
| 2026-10-22 | **D41** (decided by Claude under D509): **a dictionary says `contains(key)` and `remove_at(key)`, like a list**, one name for each thing; the old `has` and `remove` are gone. To confirm. |
| 2026-10-22 | **D42** (decided by Claude under D509; follows from D36 and from zero runtime): **a `Concurrent` runs as a resumable frame the compiler writes, and the loop that steps the frames is Spite code in `Spite.Internal`.** Every function that can wait inside a `Concurrent` is lowered a second time with its locals in a heap frame (the same slots, addressed from the frame), so a wait saves where it stopped and answers that it has not finished. A program cannot name `Spite.Internal`, and only a program that makes a handle carries any of it. To confirm. |
| 2026-10-22 | **D43** (decided by Claude under D509): **`String.index_of(text)` answers `Integer?`, null when the text is absent**, where the old specification answered -1. The library's callers narrow it already; the spec programs that print -1 (`string_methods`) wait on this. To confirm. |
| 2026-10-22 | **D44** (decided by Claude under D509): **`Parallel(work(arguments))` and `Concurrent(work(arguments))` run that call**, its arguments worked out where the handle is made, as `Parallel(work)` runs a function; the rule that no call goes inside an argument does not apply to the call a handle runs. `List.parallel_each_<member>()` is written with it in the library, a piece per `Parallel`. A singleton's function takes the singleton's lock only when it reads or writes the singleton (a function that touches nothing of it runs unguarded, so a `Parallel` calling it cannot wait on a caller that holds the lock). To confirm. |
| 2026-10-22 | **D45** (decided by Claude under D509; follows from D244): **`Arguments.get(index)` outside the arguments stops the program**, since an empty text there could not be told from an empty argument. `tests/system` printed `get(3)` of no arguments as an empty text; it now prints only the count. To confirm. |
| 2026-10-22 | **D46** (decided by Claude under D509): **a crash writes its stop line with the whole numbers its condition names, `(value=-9, limit=0)`, then the ring of failed asserts**, oldest first, each a `spite.assert` line with its site's id, place, class, function and `answered=`, and `repeated=<count>` for a site that failed several times in a row; an id is a hash of the class, the function, the assert's ordinal there and its condition. Asserts in the standard library (the folders the entry class loads before anything else) never enter the ring, and a program with no assert of its own carries no ring. `--trace-asserts` writes each line as its assert fails, and `--optimized` keeps only the id. The spec programs that expected the old report without its lines now expect these. To confirm. |
| 2026-10-22 | **D50** (decided by Claude under D509): **a question about a class's functions asked of a class the compiler knows (`$T`, a class name, `class`, a walked class) is answered while compiling**: `has_function` and `argument_count` become constants where they are read, and `function_waits` and `function_writes_parameter` become constants worked out once every function of the program is built, from a study of the built functions. A pattern `prefix<hole>suffix` matches every listed function whose name has that prefix and suffix and something between. The answer is a constant in the generated code; an `if` on one of the late answers still compiles both branches, and only the taken one runs. A question whose name is not written as text is a compile error. To confirm. |
| 2026-10-22 | **D51** (decided by Claude under D509): **what counts as a write for `function_writes_parameter` and `Spite.Argument.is_mutated`**: a write of an attribute or an element of the object passed, or of anything reached through its attributes; a call that writes the matching parameter of the function it calls, followed to a fixed point; storing the object (or anything reached through it) anywhere, since it can then change later; passing it to a function value the compiler cannot name. A singleton reached through an attribute is not part of the object, and a parameter assigned a new object names that object from then on. A number, a `Boolean`, an enum and text are never written. A function that takes a reflection object, a member template and a compiler-supplied function off the known lists (`_read...`, `_write...`, `_forget...`, `_resize...`) answer `true`, since the compiler cannot tell. | 2026-10-22 | **D52** (decided by Claude under D509): **a class object lists its functions only in a program that asks a run-time class object for them** (`.functions`, `has_function`, `argument_count` or `function_waits` on a `Spite.Class` value), and class objects are filled once compiling ends, so the list holds every function the class has by then. The list leaves out constructors, member templates, walk copies, number copies and names starting with `_`; it keeps template instances and functions the compiler writes, such as `to_debug`. `call_function()` runs a function on a stand-in at its defaults for a class of the program's own folder that is not a singleton; a function that takes arguments halts naming it; a function of a standard library class or of a singleton has no stand-in, and `call_function()` on it halts. A walk fact (`is_resumable`, `is_mutated`, `accesses`) of a function the compiler did not study halts where it is read. To confirm. |

The specification asks for a constant here; until constant reflection folds, the check runs. To confirm. |
| 2026-10-22 | **D54** (decided by Claude under D509): **a function value's `.name` and `.arguments` are read where the compiler knows its function**: named directly (`shouter.shout.name`) or held in a `var` initialised with it and never assigned again. `.returns` comes from its type. Anything else is "'Spite.Function<String, String>' has no attribute 'owner'", as `conformance/function_owner` expects, although the specification's functions page lists `.owner` (the conflict is for Mortaro). To confirm. |
| 2026-10-22 | **D55** (decided by Claude under D509): **`function.accesses` holds an entry for every attribute of the class and every argument, with what the study answers, and the dictionary keeps only those read or written**, built when it is asked. Its attributes come first in declaration order, then its arguments.
